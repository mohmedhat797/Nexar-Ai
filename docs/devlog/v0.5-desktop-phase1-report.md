## How this phase came about

After v0.4 the owner asked whether the UI/UX had been checked. A first-run review of the CLI found it
hard to start with (no setup step, only the offline echo resource by default, required flags without
defaults, noisy errors). The owner chose a **desktop app**, Windows first, that works on project
folders like Claude Cowork or the Codex app, with **Electron**, a **chat-plus-files** layout and a
**mockup first**.

The clickable mockup (private link: https://claude.ai/artifact/2XgS6QfxvKVjpuazraeojN) went through
three owner rounds:

1. Workspace (chat, files, approvals, resources, workflows, engineering) and first-run setup.
2. The owner added themes, AI behavior settings per mode (like Claude Code and Codex), scheduled tasks,
   and two modes: **Cowork** (OpenWorker responsible) and **Code** (DSH responsible).
3. The owner added a **Providers** tab: any provider, by subscription sign-in or API key.

## Decisions

- **ADR-021, Nexar Desktop**
  - Electron app, with the engine in the main process behind an `EngineHost`.
  - The renderer is untrusted: sandbox, context isolation, strict CSP, no Node, no navigation.
  - One narrow bridge to the renderer, validated with zod in the main process. No network listener.
  - Per-user state lives in `<appData>/Nexar`. Projects are added only through the native folder
    dialog, and the engine runs with the `project-only` workspace policy.
  - Modes are owner-preference defaults (Cowork → OpenWorker, Code → DSH), never separate engines.
  - Themes and AI behavior settings. The work is split into six phases.
- **ADR-022, providers and credentials**
  - Subscriptions connect only through each vendor's own sign-in and never power pi-ai or DSH.
  - API keys are encrypted with Electron `safeStorage` (DPAPI on Windows) under a new `keystore`
    credential source, resolved in the main process at call time and never sent to the renderer.
  - Key checks are free (they only list the provider's models).
- **ADR-023, scheduled tasks**
  - The scheduler runs inside the app while it is open or in the tray.
  - Every schedule needs a per-run budget. Approvals wait or skip the run; nothing is ever approved
    automatically.
- **Roadmap and backlog:** v0.5 is now Nexar Desktop, and mobile moves to v0.6. Backlog items
  NXR-050 to NXR-056 cover the phases.

## Verification

- **`pnpm check`:** 1863 tests passed, 7 skipped (opt-in live tests). That includes 9 host tests and
  58 desktop bridge tests: strict schemas, path escapes, tasks, artifacts, approvals, settings and
  first-run config.
- **`pnpm desktop:e2e`:** Playwright drives the real Electron app through these steps, and the test
  passes.
  1. Checks the window's web preferences, and that the page has no `require` or `process`.
  2. First run, add a project through the (stubbed) native dialog, preview a file.
  3. Run a task: routing card, result, and a draft stored in the project.
  4. Dark theme, then relaunch: the theme and project persisted.
  5. AI resources, Approvals, Code mode.
- **CI** runs the E2E under Xvfb on GitHub's Ubuntu runners; green on `3ff1756`.
- **Fresh-clone replay:** the whole CI sequence was replayed on a fresh clone with nothing built. It
  passes, including fetching Electron automatically when pnpm skipped its download.
- **Manual check:** screenshots of the running app in Light, Midnight and the other screens. Discovery
  found the real Claude Code on the build machine.

## Found and fixed in review

- **Opening files with the OS default program** could reach any file under the artifacts folder. It is
  now limited to the artifact store's own file types (`.md`, `.txt`, `.json`, `.csv`), so a planted
  `.exe` or `.html` is refused (with a test).
- **The renderer lint program** depended on built output; it now maps `@nexar/*` to sources.
- **Per-user state** was going to `%APPDATA%\@nexar\desktop`; it is now `%APPDATA%\Nexar`, as the ADR
  says.
- **The build script's Vite root** was wrong in the interrupted delegate run (fixed by the resumed run).

## Not done yet (honest list)

- **The app has never run on Windows.** Some unit suites assume Linux (sandbox, unix sockets, POSIX
  modes). The Windows pass is NXR-051.
- **No real-resource task was run through the app** in this phase, to avoid spending subscription
  allowance. Routing to Claude Code was shown (it was discovered and scored); running one is the first
  owner check.
- Not built yet:
  - The mockup's Setup screen.
  - Chat history across restarts.
  - Multi-message conversations (each message is its own task).
  - Providers, AI behavior wiring, scheduled tasks, Code mode, OpenWorker as the Cowork agent.
