# Nexar v0.3 — Engineering Machine: milestone completion report

Date: 2026-10-01 · Branch: `feat/nexar-v0.3-engineering-machine` (from `main` at `34e4984`, after the
v0.2 merge) · Orchestrator: Claude Opus 5.5 · Implementer: Claude Sonnet 5.5 via `claude-delegate`.

## Verdict

**v0.3 is complete.** The owner can give Nexar one engineering goal, and Nexar runs the whole chain:

1. A private git clone for the task.
2. Lanes from a data-driven plan, each routed by the Resource Controller.
3. Agents run inside a fail-closed bubblewrap sandbox with vendor-only egress.
4. The patch is harvested inside a sandbox and checked against the patch policy.
5. Gates run on a fresh clone with no network.
6. A review lane runs on a different resource.
7. The owner approves.
8. Nexar makes the commit on a new `nexar/<task>` branch.

Agents never commit and never push. Nexar never pushes.

Proved live, twice, with two different subscription-backed resources:

- **Run 1:** Codex implements and Claude Code reviews. The owner approved the commit.
- **Run 2:** Claude Code implements and Codex reviews, under the owner's `ownerApproval: never`
  policy.

`pnpm check` passes with 1,495 tests (7 opt-in tests skipped). CI also runs the real-bubblewrap
tests, using a bwrap-scoped AppArmor profile.

## Security controls

Each control is enforced in code and proven by tests. The full table with enforcing files and tests
is in [`docs/architecture/security.md`](../architecture/security.md).

- **The sandbox fails closed.** Without bwrap or socat, write lanes and gates fail with
  `SANDBOX_UNAVAILABLE`. There is no unsandboxed fallback.
- **Every write-capable adapter refuses write mode without the sandbox.** Claude Code, Codex, DSH,
  Antigravity and the Delegate Skills relay all refuse with `POLICY_REJECTED` before anything
  starts.
- **Inside the sandbox, the agent is confined:**
  - the workspace is writable, but `.git` is read-only and cannot be moved;
  - the home directory is a tmpfs;
  - host files are invisible;
  - the only network interface is loopback;
  - egress is allowed only to the resource's exact hosts.
- **No agent commits or pushes.** This holds structurally:
  - `.git` is read-only;
  - the clone has no remote;
  - the proxy denies git hosts.

  Deny rules in the adapters are defence in depth only.

- **The host never runs git in an agent's worktree.** The harvest runs inside a sandbox with
  Nexar's pristine bare clone as `GIT_DIR`. A planted `core.fsmonitor`/`diff.external` is never
  executed (real-bwrap test).
- **The patch policy denies risky paths:** `.git` (all spellings), `.gitmodules`, `.gitattributes`,
  `.github/workflows/`, gitlinks, symlinks, mode changes, oversize patches and empty patches.
- **Gates run on the harvested patch,** applied to a fresh clone with no network. They never run
  on the agent's worktree.
- **Review is independent.** The review lane runs on a different resource (diversity is `required`
  in the E2E), and an unparseable verdict counts as `request-changes`.
- **Owner approval is fingerprint-bound and single-use.** It is consumed immediately before the
  plumbing commit. The owner's working tree, index, HEAD and hooks are untouched, and nothing is
  pushed.
- **Records and telemetry hold no content.** They carry only ids, counts, codes and hashes.
  Verified on the live runs: no goal text and no absolute paths.

## Bugs found and fixed during review

- **Bridge script:** the socat bridge joined `&` with `;`, which is a shell syntax error in proxy
  mode. It is now newline-joined, and a real-bwrap test caught it.
- **Toolchain binds:** binds were emitted before `--tmpfs /tmp`, which hid any toolchain under
  `/tmp`. Found while running the real dsh. They now come after the tmpfs mounts, with a test.
- **Mount paths:** sandbox mount paths were limited to `/home/agent` and `/opt/nexar`, which was too
  narrow for runtimes with fixed credential paths. They are now a reserved-location rule (system
  dirs, `/work`, `/run`, `/tmp` and the home tmpfs itself stay protected).
- **Relay pin:** the relay could be swapped between the pin check and the launch. Nexar now runs a
  private read-only copy of the verified bytes.
- **IPv4-compatible addresses** (`::/96`) are now refused by the proxy.
- **Flaky test:** an integration test counted shared-tmpdir entries while other suites ran in
  parallel. It now uses a private run-dir base.

## Security gaps (open)

These are tracked in `security.md` and the backlog:

- **No seccomp filter yet** ([NXR-025](../backlog/025-seccomp-filter-for-sandbox.md)). Nested user
  namespaces are disabled with `--disable-userns`.
- **Env values reach bwrap's argv.** For example, a future DeepSeek key would be visible to the
  owner's own processes through `/proc`
  ([NXR-026](../backlog/026-launcher-env-via-args-fd.md)). Claude and Codex use file mounts, not env.
- **The `agy` prompt is passed in argv.**
- **The Codex home is mounted read-write** so tokens can refresh. A lane can therefore read its own
  Codex login inside the sandbox, but it can only reach the allowlisted OpenAI hosts.
- **There is no TLS inspection.** Exfiltration to an allowlisted vendor endpoint remains possible.
- **The review lane is advisory.** Gates and owner approval are the hard controls.
- **WSL-specific checks are unverified** until the owner runs the runbook.
- **The approver is not authenticated** (v0.5).
- **v0.2 read-only runs are still unsandboxed.**
