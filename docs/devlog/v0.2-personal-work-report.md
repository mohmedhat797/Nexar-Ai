## Verdict

**v0.2 is complete.**

The owner can now ask Nexar, directly or through OpenWorker, to prepare technical documentation, a
SOW, a solution proposal, or a meeting brief with a draft follow-up. Nexar validates access, picks a
resource, executes, stores the artifact, explains the routing, and never sends anything.

Honest limits:

- OpenWorker was tested live through **OpenWorker's own MCP client code** (`coworker.mcp.MCPManager`
  from v0.3.0, installed headless). It was not tested through the OpenWorker desktop agent loop,
  which needs a model API key that this environment lacks.
- DeepSeek Harness and pi-ai live model runs remain blocked on credentials (#1, #2). v0.2 did not
  need them.

## Security controls (the eight hard gates)

Each gate is mapped to its enforcing code and proving tests in
[`docs/architecture/security.md`](../architecture/security.md):

1. **Realpath containment.** The `allowed/link -> /outside` attack is rejected, and the adapter is
   never invoked.
2. **Invalid project paths fail closed.**
3. **Work Bridge authentication.**
4. **Exactly-once audit.**
5. **No secrets or content in audit or telemetry.** Verified on live output: the synthetic document
   text appears in neither.
6. **MCP stdout is protocol-only.** A process-level test checks the raw stdout bytes.
7. **Outward actions fail closed.** No executors exist.
8. **Request input cannot grant filesystem permissions.**

Hardening found during review and applied before commit:

- **Artifacts `.gitignore`:** it is now also added to a pre-existing `.nexar/`.
- **MCP request ids:** they are namespaced per client, which removes a cross-client existence oracle.
- **DSH process-group kill:** the regression test fails on the old code.

## Security gaps (open)

- **OS-level sandbox:** there is none for agent runtimes (#17, NXR-024). This is needed before v0.3
  write-capable lanes.
- **Check-then-use (TOCTOU) window** between the path check and the runtime's use of the path.
  Mitigated by passing the canonical path onward; the sandbox is the full fix.
- **Approver identity:** `decide()` does not authenticate the approver. The v0.5 control plane must.
- **`clients.json`:** writers are serialized within a process only, not across processes.
- **Prompt injection is mitigated, not prevented.** Inputs are wrapped as untrusted data. The real
  guarantee is structural: there is no outward code path.
- **Scheduled OpenWorker automations** do not load MCP tools (an upstream limitation, from source
  reading). Interactive sessions work.
- **Artifact refs** are absolute `file://` URIs. That is acceptable for the local owner, and worth
  revisiting before any remote access.

## Tests

919 passed and 4 skipped (the opt-in live tests). The run is offline and deterministic and needs no
paid calls. The new suites cover:

- **Paths:** path policy (symlink, `..`, dangling, loop), merge precedence, document sets.
- **Artifacts:** sanitization, collisions, symlinks, permissions.
- **Approvals:** allow, deny, expiry, abort, restart, single use, binding.
- **Auth and audit:** success, failure, revocation, scopes, redaction, exactly-once.
- **MCP:** in-memory client and real stdio process, plus the stdout purity check.
- **Workflows:** validation before execution, rendering, injection, no-auto-send static test.
- **CLI.**

## Technical debt

- **Workflow storage failure:** if storing fails after a successful run, the bridge returns `failed`
  and the text is lost.
- **Jobs are in memory:** MCP jobs are lost on restart, and there is no per-job cancel tool.
- **`nexar.resources`** runs probes on every call (cheap, no paid calls).
- **Template quality:** there is no evaluation loop yet; follow-up via issues as needed.
- **TypeScript 7** is still pending (#3), and streaming output is pending (#4).

## Unresolved blockers

- **DSH and pi-ai live model runs** need `DEEPSEEK_API_KEY`, a provider key, or a local
  OpenAI-compatible server (#1, #2).
- **OpenWorker desktop live chat test** needs an OpenWorker model provider key and a desktop/session.
