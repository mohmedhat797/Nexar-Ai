## Architecture as implemented

User/CLI → `Nexar.createTask` → `ResourceController.route` (registry snapshot + probes →
`DeterministicRoutingPolicy.evaluate`) → explainable `RouteDecision` → `AdapterRegistry.resolve` →
`ExecutionAdapter.execute` → `ExecutionResult` → `ExecutionRecord` → telemetry sinks.

The three questions are kept separate as designed: **who** executes (NRC), **how** work is
orchestrated (DSH or a native agent's loop), and **how** the provider is called (pi-ai or runtime
internals).

Research-driven corrections to the starting hypothesis (ADR-002, 003, 004, 011):

- DeepSeek Harness has no in-process API. Nexar drives `dsh --profile sdk` over its JSON-RPC wire
  protocol using a Nexar-owned client and has no `@deepseek-ai` npm dependency.
- DSH already embeds pi-ai, so Nexar's pi adapter is a separate direct-model path, not a layer
  underneath DSH.
- OpenWorker does not expose its agent as a service. The chosen seam is a Nexar MCP server that
  OpenWorker consumes (v0.2), and v0.1 ships the transport-agnostic bridge contract.
- The live proof runs through the native Claude Code agent, the only authenticated runtime available.

## Mocked / not live

- DSH model execution: fake runtime (protocol-faithful) in CI. **Blocked** on `DEEPSEEK_API_KEY`
  (NXR-001). To run it manually: install `@deepseek-ai/dsh@0.2.0-rc.2`, export `DEEPSEEK_API_KEY`,
  then `NEXAR_LIVE_TESTS=1 pnpm vitest run integrations/deepseek-harness`.
- pi-ai provider calls: `fauxProvider` in CI. **Blocked** on a provider key or a local
  OpenAI-compatible server (NXR-002).
- OpenWorker: contract only, by design (transport in v0.2, NXR-010).

## Security risks (open)

- No OS-level sandbox around agent runtimes; each runtime's own permission model applies
  (Claude Code defaults to read-only `plan` mode in Nexar) — NXR-024.
- DSH adapter kills only the `dsh` process, not its process group (possible orphaned grandchildren).
- Claude Code adapter strips `AWS_*`/`GOOGLE_*` credentials, which would break Claude Code configured
  for Bedrock/Vertex. This is intentional for subscription use; revisit if needed.
- Work Bridge containment check is lexical (no `realpath`), so a symlink inside an allowlisted
  directory could escape. Harden in NXR-011 before any transport is exposed.
- Free-form `runtime.options`/`metadata` in config are not scanned for secrets (only `auth` is strict).
- `.nexar/` telemetry is unencrypted at rest (mode 0600, directories 0700).

## Technical debt

- TypeScript pinned to 6.x until typescript-eslint supports 7 (NXR-003).
- No streaming output (`text-delta`) yet (NXR-004).
- CLI prints the routing explanation after execution, because `RunOptions` has no `onRouted` hook.
- `requestId` in the Work Bridge is documented as an idempotency key but is not deduplicated yet.
- Claude Code adapter buffers stdout without a size cap.
