# NXR-070 — Security Threat Model (reviewed scope)

This model covers the corrected scope in `NXR070_Implementation_Blueprint_Reviewed.md`. Threats that exist only in deferred features are listed in §4.

## 1. Trust boundaries

| ID  | Boundary                                 | Trusted side                | Untrusted side                                               |
| --- | ---------------------------------------- | --------------------------- | ------------------------------------------------------------ |
| TB1 | Renderer ↔ Desktop main IPC              | main                        | renderer (sandboxed, may be compromised by rendered content) |
| TB2 | Main ↔ adapter child processes           | main (env/home selection)   | vendor runtimes, their output                                |
| TB3 | Desktop ↔ plane protocol                 | each host for its own state | the peer's frames                                            |
| TB4 | Nexar ↔ provider APIs                    | Nexar request construction  | responses, inventories, error bodies                         |
| TB5 | Canonical history ↔ next model           | Operating layer             | prior model output, owner text, artifacts (untrusted input)  |
| TB6 | Owner settings files ↔ loader            | strict loader               | file contents (corruption, tampering)                        |
| TB7 | Engine (OpenWorker/DSH) ↔ Bridge/Gateway | grant + broker              | engine tool calls                                            |

## 3. Required multi-account scenarios (Phase D), explicit behavior

| #   | Scenario                                      | Required behavior                                                                                                                                                                                          |
| --- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | A disconnected, B active                      | A's inventory invalidated, resources removed, pins to A fail `pin.connection-removed`; B unaffected (separate generation and scope)                                                                        |
| 2   | A expires during execution                    | Running execution fails with `AUTH_REQUIRED` under its pinned decision; Control restarts at most once as a new decision (existing); no automatic move of the unit to B unless policy permits at a new unit |
| 3   | Two accounts advertise the same model         | Two distinct resource ids; NRC ranks them as separate candidates; history separate                                                                                                                         |
| 4   | Session resumes with wrong account            | Not possible: no native session crosses a turn (invariant B5); test asserts none persisted                                                                                                                 |
| 5   | Native runtime state shared                   | Prevented by per-connection homes; mismatched home rejected; Claude multi-account unsupported until spike                                                                                                  |
| 6   | Runtime exposes undocumented account identity | Ignored; never parsed or stored (no credential-derived identity)                                                                                                                                           |
| 7   | Refresh returns stale models                  | Generation guard; stale not routable; empty authoritative list removes entries (ADR-028)                                                                                                                   |
| 8   | Credential reference renamed/migrated         | Built-ins never renamed; owner names immutable per connection; rename = new connection                                                                                                                     |
| 9   | Model on A but not B                          | Only A materializes it; pin on B-qualified id cannot exist                                                                                                                                                 |
| 10  | Concurrent executions on A and B              | Separate scopes, homes, generations; shared `DelegationUnitLimit` per turn still applies                                                                                                                   |

## 4. Deferred-feature threats (out of reviewed scope)

ACP frame/schema injection, ACP permission-mode mapping (Auto → bypass/full access), HTTP MCP passthrough (ACP v2 `session.mcp.http`), native resume across accounts, fork state copying, cross-host allocation and credential federation. Each needs its own ADR and threat model before implementation.

## 5. Priority

The T-01, T-02, T-04, T-05 and T-06 tests gate 070A′/B′. The T-15 and T-16 tests gate 070D′. The T-10 and T-11 tests gate 070I′.
