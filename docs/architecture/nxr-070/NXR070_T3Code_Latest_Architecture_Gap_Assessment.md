## D′ compatibility review recommendations

T3 `resolveCodexHomeLayout` returns direct or authOverlay layouts. An overlay's continuation key names the **shared** home. `materializeCodexShadowHome` keeps auth/auth-lock/model cache private while linking other shared entries; it rejects private-entry symlinks and path conflicts. Its tests explicitly exercise preserved private auth, shared-state links and symlink-capability-dependent behavior. That is account-auth separation with deliberately shared sessions/configuration, not Nexar's required full independent home boundary. [E04]

Nexar D′ must stay with fixed-root home derivation, marker ownership, private ACL/mode before first CLI write, per-connection inventory, minimal env, process leases, explicit same-account re-login and guarded Delete-home. These are already accepted requirements, not discoveries requiring a new design. [N02/N11]

Non-invasive review checklist for D′'s eventual exact head:

- Confirm two homes never share continuation/session/config/cache directories through links or inherited defaults. A new visible connection name does not prove this.
- Cover parent/root/leaf symlink or Windows reparse-point substitution, missing/mismatched marker, case/slash aliases and homes outside the fixed local root. Never delete vendor default or owner-declared homes.
- Hold admission lease through login, inventory, probe and execution until the actual owned child settles; UI state becoming idle is insufficient proof.
- Reject old-generation inventory/status replies after disable, rotation, re-login, removal or rollback. Probe failure preserves uncertainty and does not initiate login.
- Verify CODEX_HOME mismatch refuses before spawn; parent API-key vars never switch billing; logs/errors/IPC contain neither secret content nor native paths/subjects.
- Explicitly test owner-connections rollback, removed pins, tombstones and history retention. Preserve built-in `openai.subscription` semantics.
- Do not claim provider-verified identity from owner assertion. External login into a private home remains the already accepted residual risk.

If these tests already exist/pass, add no duplicate work. Any conflict with D′'s approved independent-home design needs a separate owner decision. This study has not reviewed Claude's moving uncommitted implementation, and recommends no change to its active branch.

## Security assessment and hard gates

| Boundary / threat                                   | Required response                                                                                                                                                 |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Renderer compromise, forged IDs, token substitution | Strict IPC input/output schemas, current-state main-process check, action-bound confirmation and generation binding; no path/env/secret-return fields             |
| Account confusion, identity spoofing                | Immutable connectionKey; asserted ≠ verified; differing account rejected; no silent rebinding                                                                     |
| Filesystem traversal, symlink/reparse substitution  | Fixed-root derivation, canonical containment, markers, private ACL/mode and owned-process guards; no renderer-selected homes                                      |
| Process leaks/resource exhaustion                   | Bounded cancellation, child-process ownership, deadlines, generation-aware completion, no arbitrary PID killing                                                   |
| Replay/duplicate execution                          | Restart marks interrupted; fresh approval/admission for retry; no queue adoption                                                                                  |
| Prompt injection/cross-provider contamination       | Prior outputs remain untrusted; required constraints retained under versioned context; transfer coverage visible; no tool/permission carry-over                   |
| Logs/telemetry leakage                              | Allowlisted fixed errors/scalars; sentinel tests across URL/query/stack/native stderr; avoid prompts, subjects, labels, paths and secret-key names in attribution |
| Quota/entitlement uncertainty                       | Source/freshness/coverage explicit; no login→quota inference, undocumented endpoint scraping, user-agent identity spoofing or unsupported entitlement bypass      |
| Remote control and revocation                       | Keep local Desktop/Plane boundaries; no broad HTTP MCP or federation from T3                                                                                      |

No wholesale adoption passes these gates. P0 Electron maintenance is a separately scoped security proposal; no new ADR is needed for a compatible exact-pin patch, but assignment approval is still required. A new secret-provider authority, canonical branching/native persistence, remote federation, durable replay or change to independent-home semantics would require explicit architectural authorization. Repeated owner decisions OD-1..15 are not reopened here.
